# 操作手册

面向日常使用，按「准备 → 启动 → 下载 → 数据处理 → 入库更新」的顺序说明。大部分操作在看板上完成。

## 1. 项目简介

本工程从 `GlobalBuildingAtlas LoD1 WFS` 拉取带高度字段的建筑数据，处理成可直接入库/使用的成果，并登记入库状态。整体链路：

```
WFS 建筑数据 → 下载（分块/合并/交付 SHP） → 数据处理（切分→校验→清洗→3857） → 入库 world_building → 看板登记
```

看板页签与链路对应（另有「配置」页签）：

- **建筑数据下载**：控制下载、调整队列优先级、查看进度与失败任务。
- **数据处理**：把已下载的 SHP 切分 → QGIS 校验 → 清洗 → EPSG:3857 重投影，产出交付成果。
- **库表更新**：登记哪些区域已更新进数据库。
- **配置**：配置数据库连接、区域成果共享目录、QGIS 安装目录，并可检测环境。

## 2. 首次上手（最短路径）

> **前提**：任务清单 `data/world_building_download_tasks.csv` 随仓库自带（其来源见第 5 节），已就绪。

1. 拉取/更新代码（见第 3 节「拉取更新」）。
2. 准备环境：推荐先运行根目录 `setup.ps1` 一键装好两个工具环境与主链依赖（见第 3 节）；再到「配置」页填好数据库 / 共享目录 / QGIS，点「检测环境」应显示“环境正常”。
3. 双击项目根目录 `启动.bat`，浏览器打开 `http://127.0.0.1:8765/`。
4. 「建筑数据下载」页点「重启批处理」开始下载。→ 顶部显示“批处理：运行中”，队列任务数逐步减少；下载完成后**自动登记**到处理队列。
5. 「数据处理」页 →「开始执行」。→「当前处理任务」出现条目、分片进度增长；完成后把成果 `out_data/<前缀>_pipeline/final/*_3857.shp` 拷到共享目录，再到「库表更新」页点「更新到库」登记。

> 建议先只跑**一个小区域**（如某小城市）确认整条链路通畅，再放开全量。

## 3. 前置准备

### 需安装的软件
- Python 3.12（运行所有脚本）。
- uv（建虚拟环境/装依赖；没有也没关系，见下「一键部署」）。
- Git（拉取代码）。
- QGIS 3.34.8 LTR（仅数据处理需要）。
- PostgreSQL + `psql`（重导任务清单、SHP 入库时需要）。

### 一键部署（推荐）

**前提**：装好 Python 3.12+（有 uv 更好）；已克隆代码；能联网。QGIS 需另装，一键部署不含。

**操作**：进入仓库根目录，执行：
```powershell
powershell -ExecutionPolicy Bypass -File setup.ps1
```
脚本会：① 用 uv（无 uv 时用 venv+pip）建好两个工具环境；② 给系统 Python 装 `requirements-main.txt` 依赖；然后提示下一步。

完成后：双击 `启动.bat` → 「配置」页填写 → 点「检测环境」确认全绿。

可选：`-SkipMain` 只建工具环境；`-SkipTools` 只装主链依赖。

### Python 依赖（手动安装，等价命令）
```powershell
python -m pip install -r requirements-main.txt   # 主下载链（系统 Python）
uv sync --project Tools\Oneshp_pipline_qgis       # 处理工具
uv sync --project Tools\Twopyshp2pgsql            # SHP 入库工具
```

### 需要配置（配置项清单）

**A. 看板「配置」页**（保存到 `data/config.json`，本机文件，不纳入版本控制）

**B. 环境变量（按需）**

| 变量 | 是否必需 | 说明 |
|---|---|---|
| `PGPASSWORD` | 可选 | 导出任务清单时的兜底口令；默认已从 `data/config.json` 读取数据库连接 |
| `GBA_WFS_MIN_INTERVAL` | 可选 | WFS 请求最小间隔，默认 1.05 秒 |
| `QGIS_DIR` | 可选 | 覆盖 QGIS 安装目录（看板启动处理时会自动注入；CLI 直跑时可手动设置） |

**C. 命令行 / 工具级**（不使用看板、直接跑脚本时）

| 配置 | 位置 | 说明 |
|---|---|---|

| QGIS 默认路径 | `Tools/Oneshp_pipline_qgis/src/shp_pipeline_qgis/paths.py` | 默认 `D:\QGIS`，可被环境变量 `QGIS_DIR` 覆盖 |

**D. 机器 / 运维**

| 配置 | 位置 | 说明 |
|---|---|---|
| git 代理 | 根目录 `拉取更新.txt` | `git -c http.proxy=...`；无代理删掉该参数 |
| 防火墙入站 `8765` | 系统防火墙 | 局域网访问看板时放行 |
| 工具虚拟环境 | `Tools\Twopyshp2pgsql\.venv`、`Tools\Oneshp_pipline_qgis\.venv` | 用 `uv sync --project ...` 或根目录 `setup.ps1` 创建；缺失时「配置 → 环境 / 诊断 → 检测环境」会提示 |

**通常无需修改（已有默认值）**：任务清单 `data/world_building_download_tasks.csv`、状态库 `data/*.db`、本地边界 `data/boundaries`、下载目录 `data\洲\国家\城市`，以及 `--shp-max-features` 等运行参数。

> 说明：批处理并发参数 `tile-workers` 在看板上**固定为 2**，它指**单个任务内并发抓取的格网数**，并非“同时下载的任务数”；任务是依次下载的。

> 更完整的部署清单见 `README.md` 的「部署环境清单」。

### 看板「配置」页签

启动看板后，切到「配置」页签。页面左侧为分类导航（**数据库连接 / 区域成果共享目录 / QGIS / 环境·诊断**），点击切换右侧内容；填写后点「保存」写入 `data/config.json`：

- **数据库连接**：主机 / 端口 / 库名 / 用户名 / 密码。
- **区域成果 SHP 共享目录**：形如 `\\<服务器>\BuildingData\AutoGenerte`。
- **QGIS 安装目录**：形如 `D:\QGIS`（启动处理队列时以此注入环境变量 `QGIS_DIR`，供数据处理调用 QGIS）。

页面下方是 **「环境 / 诊断」** 区：

- 列出仓库根目录、入库工具解释器（含 Python 版本）、入库脚本、入库日志目录、处理工具解释器、QGIS（`qgis_process`）及其**存在/缺失**状态。
- 点 **「检测环境」** 按钮做一次完整检测（含解释器能否导入依赖）：结果用**浮层提示**（「环境正常」/「检测到缺失/异常：…」），并在下方逐项列出明细。

后续「更新到库」会读取这里的数据库连接与共享目录；数据处理会读取 QGIS 安装目录。

## 4. 如何启动

- 双击项目根目录的 `启动.bat`，即可启动看板。
- 浏览器打开 `http://127.0.0.1:8765/`（局域网用 `http://<本机IP>:8765/`，首次访问需放行防火墙 8765 端口）。

看板有四个页签：

- **建筑数据下载**：查看下载进度、任务队列，控制批处理、调整优先级。
- **数据处理**：把已下载的 SHP 做切分 → 校验 → 清洗 → 3857 重投影。
- **库表更新**：登记哪些区域已更新进数据库。
- **配置**：配置数据库连接、共享目录、QGIS，并可检测环境。

> 若启动看板时设置了 `--action-token`，控制类/删除类操作会先弹出令牌输入框（令牌保存在浏览器本地）。

> 打开看板时会**自动检查配置**：若尚未填写配置（无 `data/config.json`）或环境项缺失，页面**顶部会出现红色提示条**。点「去配置」按第 3 节填写并点「检测环境」；点「关闭」后**本会话不再提示**。

## 5. `world_building_download_tasks.csv` 的来源

这份清单是下载与处理任务的**事实来源**，由脚本从 PostgreSQL 数据库导出生成：

- 来源：PostgreSQL 表 `world_building`（按 `continent / country / city` 分组去重）。
- 生成脚本：`scripts/export_world_building_tasks.py`，默认输出 `data/world_building_download_tasks.csv`。
- 五列含义：

  | 列 | 含义 |
  | --- | --- |
  | `continent` | 洲 |
  | `country` | 国家 |
  | `city` | 城市/区域（第三级目录名） |
  | `download_dir` | 下载目录，规则为 `data\洲\国家\城市` |
  | `process_name_prefix` | 命名前缀，取 `shp_name` 第一个下划线前的部分 |

本质上，**这份清单反映“数据库里已登记的区域”**，因此下载与处理都围绕它展开。

### 术语速查

| 术语 | 含义 |
| --- | --- |
| 洲 / 国家 / 区域 | 任务的三级划分，对应 `download_dir` 的三级目录 |
| 命名前缀 `process_name_prefix` | 处理阶段文件名的开头，取自清单第 5 列 |
| 交付 SHP | 可直接使用的成果 `<前缀>_buildings_height_gba.shp` |
| 分卷 | 数据量超过阈值时拆分出的 `..._part1.shp`、`..._part2.shp`… |
| 等待重新下载 | 某区域的原始数据被删除、待重新下载时处理任务的中间状态 |
| 库表更新 | 登记各区域是否已入库的看板页签（数据存 `data/db_update_status.json`） |

## 6. 建筑数据下载

### 如何启动

1. 打开看板「建筑数据下载」页签。
2. 在「批处理控制」点「重启批处理」开始下载；「停止下载任务」可随时停止（已完成分块会复用，断点续跑）。

> 下载任务来自**任务清单** `data/world_building_download_tasks.csv`（其来源见第 5 节）。

本页按钮说明：

- **重启批处理**：重启下载批处理；已完成分块复用，任务断点续跑。
- **停止下载任务**：停止当前下载批处理（不重启）。

> 说明：任务**下载完成后会自动登记到「数据处理」队列**，无需手动同步，之后到「数据处理」页签直接处理即可。

### 如何设置优先级

- 在「队列（全部待执行任务）」的「排序」列操作：`↑` 上移、`↓` 下移、`⤒` 置顶。
- 搜索某个城市后，命中的任务也能直接置顶（不限于队首那条）。
- 注意：**排序改动在下次启动批处理时生效**；点「重启批处理」可立即套用。

队列区其余按钮/控件：

- `搜索城市` + **搜索** / **清除**：按城市中英文模糊搜索、清空搜索。
- `每页`（15/30/50/100/200）+ **首页 / 上一页 / 下一页 / 末页**：分页浏览。
- 工具栏分左右两组（左：搜索；右：分页）；表格**表头在页面滚动时置顶**。

### 当前任务

下载进行中时，「当前任务」区显示正在下载的任务。

- **停止当前任务并加入队尾**：停止该任务并把它排到待执行队尾（顺序在下次启动批处理时生效）。

### 最近完成（重新下载）

在「最近完成」列表中，每行有：

- **重新下载**：删除该区域的下载目录并退回下载队列重下（「重下次数」+1）；对应处理任务转为「等待重新下载」（下载完成后自动恢复为待处理）；同时**删除该区域在「库表更新」页签的记录**（需重新入库登记）。

### 失败任务（重新入队）

下载失败的任务会出现在「失败任务」列表。

- **重新入队**：把该任务重置为待执行并**添加到队首**（清空尝试次数与最后错误，**不删除已下载数据**），下次启动批处理时生效。

## 7. 数据处理

把下载完成的 SHP 依次做：切分 → QGIS 有效性校验 → 清洗 → EPSG:3857 重投影。

### 如何设置处理数量

1. 打开看板「数据处理」页签。
2. 点「同步队列」，把可处理的数据登记进队列（下载完成的任务会**自动登记**，这里用于补充历史数据或手动合并后的数据）。
3. 在「数量」框填本次要处理的数量（填 `0` 表示全部待处理）。
4. 需要时勾选「资源不足时等待」（内存/磁盘不足时自动等待）。
5. 点「开始执行」；点「停止处理」可停止（会把进行中的任务重置为待处理，可再次开始续跑）。

处理控制区按钮/控件：

- `数量`（0=全部）：本次处理多少个待处理任务。
- `资源不足时等待`：内存/磁盘不足时自动等待，满足后再继续。
- **开始执行**：在后台启动处理队列（独立进程，重启看板不影响）；SHP≥2 且未合并的任务会被**跳过**（见「多个 SHP 先合并为一个」）。
- **停止处理**：停止处理队列，并把正在跑的任务重置为待处理（可再次续跑）。
- **同步队列**：扫描可处理的数据并登记进处理队列。

### 多个 SHP 先合并为一个

当数据量超过阈值时，交付成果会被拆成多个分卷 `..._part1.shp`、`..._part2.shp`…

**合并的原因：为了同初版数据库中的命名保持一致**（数据库按单个 `shp_name` 命名，分卷会导致命名对不上）。

**未合并不会被处理**：待处理队列中 SHP≥2 的任务行内会显示橙色提示「⚠ 需先合并（N 个分卷）后方可处理」，点「开始执行」时这些任务会被**跳过**（日志打印 `[SKIP] ... 需先合并`），只有在合并为 1 个 SHP 后才会进入处理；SHP 为 1 个时「自动合并」按钮置灰（无需合并）。合并完成后该行提示消失、按钮转灰。

有两种合并方式：

**方式一：自动合并（推荐）**

1. 在「待处理队列」表格中，找到该区域这一行（「SHP」列显示多个，行内会显示橙色提示「⚠ 需先合并（N 个分卷）后方可处理」）。
2. 点该行末尾的「自动合并」按钮，确认后系统在后台用本机 QGIS/GDAL 自动合并为一个 SHP。
3. 合并状态就显示在**该行末尾**（「自动合并」按钮右侧）：`合并中 x/y…` → 成功 `已合并` / 失败 `失败：<原因>`；合并进行中按钮**保持禁用**，完成后会自动**删除原分卷**并**自动同步队列**（该行「SHP」变为 1，任务回到「待处理」）。
4. 若失败（如合并后某个 `.shp`/`.dbf` 单文件预计超过约 1.9GB（Shapefile 单文件上限约 2GB）、分卷缺失等），行末会显示失败原因；鼠标悬浮可看完整信息，可排查后重试。

**方式二：手动合并**

1. 在 **QGIS** 中打开这些分卷 SHP。
2. 使用「矢量 → 数据管理工具 → 合并矢量图层」（Merge Vector Layers）合并为一个图层。
3. 导出为一个 SHP，命名与数据库保持一致（形如 `<前缀>_buildings_height_gba.shp`），放回原区域目录，并删除原分卷。
4. 回到看板「数据处理」页签点「同步队列」。系统会按新的 SHP 文件重新扫描与登记：按**合并后的 SHP 数量**更新任务，源文件变化时会把该区域已完成的任务自动重置为待处理。

确认数量无误后，再按上面的方式设置处理数量并「开始执行」。

「待处理队列」其余按钮/控件：

- 「排序」列 **↑ 上移 / ↓ 下移 / ⤒ 置顶**：调整处理顺序（下次执行处理生效）。
- 行内 `备注`：可直接编辑（≤200 字），失焦或回车**自动保存**，重跑/同步不会清空。
- 「操作」列 **自动合并**：SHP 多于 1 个时可用（行内显示「⚠ 需先合并」提示）；SHP 为 1 个时**置灰**（无需合并）。见上「多个 SHP 先合并为一个」。
- 「待处理队列」与「最近完成」表格的**表头在页面滚动时置顶**。

### 重做处理 / 重新下载

在「最近完成」列表中，每行有「操作」列，两个按钮含义不同：

| 按钮 | 作用 | 删除下载数据 | 库表更新记录 |
| --- | --- | --- | --- |
| **重做处理** | 删处理产物与输入副本（**保留下载数据**）→ 重置待处理并置顶 | 否 | **重置为未更新** |
| **重新下载** | 删**下载目录** + 处理产物 → 退回下载队列重下（与下载页的「重新下载」是**同一操作**） | 是 | **删除该记录** |

- 点「重新下载」后，该区域在「数据处理」中会变成 **“等待重新下载”** 状态（左侧计数卡片可见），不会出现在「待处理队列」里，避免误导。
- **自动恢复**：重新下载完成后，系统会自动把它改回「待处理」，无需手动点「同步队列」（前提是未关闭自动登记）。若使用了 `--no-process-sync`，则需手动点「同步队列」。
- 最近完成分页：`每页`（10 条）+ **首页 / 上一页 / 下一页 / 末页**。

> **重做类按钮一句话对照**：**重新下载**＝删下载数据 + 删处理产物 + **删**库表更新记录；**重做处理**＝保留下载数据 + 删处理产物 + 库表更新记录**重置为未更新**；**重新入队**＝只重置入队，**不删任何数据、不改库表更新记录**。

左侧卡片（计数）：

- 处理任务、运行中、待处理、已完成、**等待重新下载**、失败/阻塞。

### 失败 / 阻塞

- **重新入队**：把失败任务重置为待处理并**添加到队首**（清空阶段与错误，尝试次数保留），下次执行处理时生效。
- 「等待重新下载」是另一类状态（见上），不属于「失败 / 阻塞」。

## 8. 如何进行库表更新

处理完成后，把成果交付并写入数据库，再在看板登记。

### 交付并写入数据库

1. 把区域成果 SHP 放到共享目录：`<配置页签中的共享目录>\<洲>\<国家>\<区域>\`（例如 `\\<服务器>\BuildingData\AutoGenerte\亚洲\中国\台湾`）。
2. 打开看板「库表更新」→「**未更新到库**」，点该行的「**更新到库**」按钮：
   - 系统**先检查**共享目录内容与处理产物 `out_data/<前缀>_pipeline/final/*_3857.shp` 是否一致；
   - **一致** → 后台执行入库（删除该 洲/国家/区域 旧记录，再按目录内每个 `*.shp` 的 3857 包围盒写入 `world_building`），成功后**自动登记为「已更新」**；
   - **不一致** → 弹出提示框列出缺失/多余文件，并浮层提示“内容不一致”，**不执行**。
   - 结果用**浮层提示**：成功「入库完成，已登记为已更新」、失败「入库失败：<原因>」；入库进行中按钮**保持禁用**。

> 数据库连接与共享目录取自看板「配置」页签。若需手动执行，命令等价于：
> ```powershell
> & "Tools\twopyshp2pgsql\.venv\Scripts\python.exe" "Tools\twopyshp2pgsql\main3_region.py" `
>   --continent "<洲>" --country "<国家>" --region "<区域>" `
>   --root "<共享目录>" --log-dir "data\logs\update"
> ```
> 运行日志保存在 `data\logs\update\` 目录。

### 在看板上登记

- 使用「更新到库」按钮：入库成功后**自动**登记为「已更新」（表格按已更新状态分为「未更新到库 / 更新到库」两栏），无需手动标记。
- **备注**：两栏都可直接编辑，**失焦或回车自动保存**（仅内容变化时提交）；成功/失败用浮层提示。
- **更新时间**：由入库成功后自动填入，**只读**（仅「更新到库」栏显示）。

本页按钮/控件：

- 子选项卡 **未更新到库 / 更新到库**（默认停在「未更新到库」）：按已更新状态筛选。
- `每页`（15/30/50/100/200）+ **首页 / 上一页 / 下一页 / 末页**：分页浏览。
- 行内：`更新时间`（只读，仅「更新到库」栏）、`备注`（可编辑，失焦自动保存）。
- **更新详情列**（仅「更新到库」栏显示）：显示最近一次入库的结果，形如 `删除 X 条 / 新增 Y 个 SHP`（有跳过则补 `/ 跳过 Z`）；鼠标悬浮可看状态与时间。
- **操作列**：仅「未更新到库」的行提供「更新到库」按钮（先检查共享目录与处理产物是否一致，再执行入库）。

说明：若之后重做该区域，标记会同步处理——「重做处理」把标记**重置为未更新**；「重新下载」（下载页与处理页行为一致）**删除该记录**，需重新入库登记。

## 9. 常见问题

- **`git pull` 连不上 GitHub**：使用代理（见第 3 节「拉取更新」，`-c http.proxy=...`）；无代理时删掉该参数。
- **报 `No Python at '...'`**：说明拷贝了别的机器的 `.venv`（不可移植）；删除后运行对应工具的 `setup.ps1` 重建。
- **数据处理报 QGIS 相关错误**：确认已安装 QGIS，并在「配置」页「QGIS 安装目录」填对路径（等价环境变量 `QGIS_DIR`）；未配置时回退到 `Tools/Oneshp_pipline_qgis/src/shp_pipeline_qgis/paths.py` 的默认值。
- **「更新到库」失败**：确认看板所在机器能访问「配置」页填写的**数据库**与**共享目录**（连不上或内容不一致时会有浮层/弹窗提示）；共享目录里该区域的文件需与处理产物一致（见第 8 节）。
- **点「开始执行」没反应**：先确认已「同步队列」（队列非空）；再看 `data/logs/process/run.log`；若提示资源不足，勾选「资源不足时等待」或先释放磁盘/内存。
- **下载不动**：确认批处理已启动、待执行队列非空；源站有限流（约 60 请求/分钟），过密会变慢或等待重试。
- **日志位置**：下载 `data/logs/download/run.log`；处理 `data/logs/process/run.log`；入库 `data/logs/update/`；看板自身 `data/logs/server/server.log`。

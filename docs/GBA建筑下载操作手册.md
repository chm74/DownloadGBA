# GBA 建筑数据下载操作手册

面向日常使用，按「准备 → 下载 → 数据处理 → 拷贝交付 → 更新到库」的顺序说明。大部分操作在看板上完成。

## 1. 项目简介

本工程从 `GlobalBuildingAtlas LoD1 WFS` 拉取带高度字段的建筑数据，处理成可直接入库/使用的成果，并登记入库状态。整体链路（各步骤的看板入口见第 2 节步骤表）：

```
任务清单 CSV（来源=数据库已登记区域，见第 5 节） → 清单同步到状态库 → 下载（修改优先级→开始下载→分块/合并/交付 SHP；完成自动登记处理队列） → 数据处理（切分→QGIS校验→清洗→3857） → 拷贝到共享目录 → 更新到库 world_building → 看板登记
```

看板页签与链路对应（共六个页签）：

- **建筑数据下载**：控制下载（未运行时按钮为「开始下载」，运行中为「重启下载」）、修改队列优先级（`↑` 上移 / `↓` 下移 / `⤒` 置顶）、查看进度与失败任务。
- **数据处理**：把已下载的 SHP 切分 → QGIS 校验 → 清洗 → EPSG:3857 重投影，产出交付成果。
- **库表更新**：登记哪些区域已更新进数据库。
- **日志**：集中浏览与查看各阶段日志（见第 9 节）。
- **CSV清单管理**：检查 / 追加任务清单（追加后自动同步到下载状态库，新任务加入下载队首）。
- **配置**：配置数据库连接、区域成果共享目录、QGIS 安装目录，并可检测环境。

## 2. 整个链路步骤（首次上手最短路径）

> **前提**：任务清单 `data/world_building_download_tasks.csv` 随仓库自带（其来源见第 5 节），已就绪。

整个链路 =「准备 → 下载 → 数据处理 → 拷贝交付 → 更新到库」，全部在看板上完成：

| 步骤 | 看板位置 | 关键操作 | 完成后 |
| --- | --- | --- | --- |
| ① 准备 | 配置 | 启动看板，核对数据库/共享目录/QGIS，点「检测环境」 | 显示“环境正常”（第 3 节） |
| ② 下载 | 建筑数据下载 | （可选）把目标区域**置顶**（运行中无需重启，当前任务完成后生效） → 未运行时点「开始下载」 | 成功任务进「最近完成」（失败进「失败任务」），并**自动登记**到处理队列（第 6 节） |
| ③ 数据处理 | 数据处理 | 多分卷任务先「自动合并」（第 7 节）→ 点「开始执行」（数量取「配置」页「处理默认数量」） | 切分→QGIS校验→清洗→3857 完成，产物在 `out_data/<前缀>_pipeline/final/` |
| ④ 拷贝交付 | 库表更新 → 未更新到库 | 点「拷贝到共享目录」（也可手动拷贝） | 成果发布到共享目录并校验一致，`final` 被清空（第 8 节） |
| ⑤ 更新到库 | 库表更新 → 未更新到库 | 点「更新到库」 | 入库成功，**自动登记**为「已更新」（第 8 节） |

最短路径：

1. 拉取/更新代码（见第 3 节「拉取更新」）。
2. 准备环境：推荐先运行根目录 `setup.ps1` 一键装好两个工具环境与主链依赖（见第 3 节）；配置已随仓库自带 `data/config.json`，一般**无需重填**（如需改用本机地址，可直接编辑该文件或在「配置」页保存），点「检测环境」应显示“环境正常”。
3. 双击项目根目录 `启动.bat`，浏览器打开 `http://127.0.0.1:8765/`。
4. 「建筑数据下载」页点「开始下载」。→ 顶部显示“批处理：运行中”，队列任务数逐步减少；下载完成后**自动登记**到处理队列。
5. （可选）想让某个区域先下载：在「队列（全部待执行任务）」按城市搜索并点「⤒ 置顶」；运行中无需重启，当前任务完成后按新顺序执行（未运行时点「开始下载」；见第 6 节「如何下载」与「如何修改优先级」）。
6. 「数据处理」页 →「开始执行」。→「当前处理任务」出现条目、分片进度增长；完成后到「库表更新」→「未更新到库」，先点该行「**拷贝到共享目录**」（自动把处理成果 `out_data/<前缀>_pipeline/final/*_3857.shp` 发布到共享目录，并删除 final），再点「**更新到库**」登记。

> 任一步出错：先看「日志」页对应任务日志（见第 9 节）。建议先只跑**一个小区域**（如某小城市）确认整条链路通畅，再放开全量。

## 3. 前置准备

### 需安装的软件
- Python 3.12（运行所有脚本）。
- uv（建虚拟环境/装依赖；没有也没关系，见下「一键部署」）。
- Git（拉取代码）。
- QGIS 3.34.8 LTR（仅数据处理需要）。
- PostgreSQL + `psql`（重导任务清单、SHP 入库时需要）。

### 一键部署（推荐）

**前提**：装好 Python 3.12+（有 uv 更好）；已克隆代码；能联网。QGIS 需另装，一键部署不含。

**操作**：进入仓库根目录，执行：
```powershell
powershell -ExecutionPolicy Bypass -File setup.ps1
```
脚本会：① 用 uv（无 uv 时用 venv+pip）建好两个工具环境；② 给系统 Python 装 `requirements-main.txt` 依赖；然后提示下一步。

完成后：双击 `启动.bat` → 核对「配置」页（`data/config.json` 随仓库自带，一般无需修改）→ 点「检测环境」确认全绿。

可选：`-SkipMain` 只建工具环境；`-SkipTools` 只装主链依赖。

### Python 依赖（手动安装，等价命令）
```powershell
python -m pip install -r requirements-main.txt   # 主下载链（系统 Python）
uv sync --project Tools\Oneshp_pipline_qgis       # 处理工具
uv sync --project Tools\Twopyshp2pgsql            # SHP 入库工具
```

### 需要配置（配置项清单）

**A. 看板「配置」页**（随仓库自带 `data/config.json`；可直接编辑该文件，或在「配置」页填写后保存）

| 配置项 | 是否必需 | 说明 |
|---|---|---|
| 数据库连接（host/port/dbname/user/password） | 入库/导出需要 | 「更新到库」按此连接 PostgreSQL；默认 `172.16.1.145` / `5432` / `building` / `postgres`（随仓库自带，可改） |
| 区域成果 SHP 共享目录 `result_root` | 入库需要 | 形如 `\\<服务器>\BuildingData\AutoGenerete`；默认 `\\172.16.0.116\BuildingData\AutoGenerete` |
| QGIS 安装目录 `qgis_dir` | 处理需要 | 形如 `D:\QGIS`；启动处理时注入环境变量 `QGIS_DIR`（默认 `D:\QGIS`） |
| qgis_process 路径 `qgis_process_bat` | 可选 | 直接指定 `qgis_process-qgis.bat` 的完整路径，如 `D:\QGIS\bin\qgis_process-qgis.bat`；留空时按 `qgis_dir\bin\qgis_process-qgis.bat` 自动推导。启动处理时注入 `QGIS_PROCESS_BAT` |
| 处理默认数量 `process.default_limit` | 可选 | 每次「开始执行」处理的待处理任务数（`0`=全部）；修改保存后，在**下一次**「开始执行」时生效（不影响正在运行的处理） |

**B. 环境变量（按需）**

| 变量 | 是否必需 | 说明 |
|---|---|---|
| `PGPASSWORD` | 可选 | 导出任务清单时的兜底口令；默认已从 `data/config.json` 读取数据库连接 |
| `GBA_WFS_MIN_INTERVAL` | 可选 | WFS 请求最小间隔，默认 1.05 秒 |
| `QGIS_DIR` | 可选 | 覆盖 QGIS 安装目录（看板启动处理时会自动注入；CLI 直跑时可手动设置） |
| `QGIS_PROCESS_BAT` | 可选 | 直接指定 `qgis_process-qgis.bat` 完整路径，优先于 `QGIS_DIR` 推导（看板按「配置」页自动注入） |

**C. 命令行 / 工具级**（不使用看板、直接跑脚本时）

| 配置 | 位置 | 说明 |
|---|---|---|
| 数据库 + 共享目录 | `Tools/twopyshp2pgsql/.env`（`PG_*`、`DATA_ROOT`） | **仅直接跑 `main3_region.py` 时用**；走看板「更新到库」以「配置」页为准，**不读该 `.env`** |
| QGIS 默认路径 | `Tools/Oneshp_pipline_qgis/src/shp_pipeline_qgis/paths.py` | 默认 `D:\QGIS`；可被 `QGIS_DIR` 覆盖，`QGIS_PROCESS_BAT` 可直接指定批处理文件 |

**D. 机器 / 运维**

| 配置 | 位置 | 说明 |
|---|---|---|
| git 代理 | 根目录 `拉取更新.txt` | `git -c http.proxy=...`；无代理删掉该参数 |
| 防火墙入站 `8765` | 系统防火墙 | 局域网访问看板时放行 |
| 工具虚拟环境 | `Tools\Twopyshp2pgsql\.venv`、`Tools\Oneshp_pipline_qgis\.venv` | 用 `uv sync --project ...` 或根目录 `setup.ps1` 创建；缺失时「配置 → 环境 / 诊断 → 检测环境」会提示 |

**通常无需修改（已有默认值）**：任务清单 `data/world_building_download_tasks.csv`、状态库 `data/*.db`、本地边界 `data/boundaries`、下载目录 `data\洲\国家\城市`，以及 `--shp-max-features` 等运行参数。

> 说明：批处理并发参数 `tile-workers` 在看板内**固定为 2**（页面不再显示该参数），它指**单个任务内并发抓取的格网数**，并非“同时下载的任务数”；任务是依次下载的。

### 看板「配置」页签

启动看板后，切到「配置」页签。页面左侧为分类导航（**数据库连接 / 区域成果共享目录 / QGIS / 数据处理 / 环境·诊断**），点击切换右侧内容；填写后点「保存」写入 `data/config.json`：

- **数据库连接**：主机 / 端口 / 库名 / 用户名 / 密码。
- **区域成果 SHP 共享目录**：形如 `\\<服务器>\BuildingData\AutoGenerete`。
- **QGIS 安装目录**：形如 `D:\QGIS`（启动处理队列时以此注入环境变量 `QGIS_DIR`，供数据处理调用 QGIS）。
- **qgis_process 批处理文件**：可直接指定 `D:\QGIS\bin\qgis_process-qgis.bat`（或自定义安装位置的同名文件）。留空时自动按「QGIS 安装目录」推导；填写后以填写的完整路径为准，启动处理时注入 `QGIS_PROCESS_BAT`。
- **数据处理**：处理默认数量（`0`=全部）——每次点「开始执行」时读取的处理任务数；保存后对**正在运行**的处理无效，需先「停止处理」再「开始执行」。

页面下方是 **「环境 / 诊断」** 区：

- **仓库根目录**为只读诊断信息，默认取**启动看板时的当前工作目录**（双击 `启动.bat` 时会先切换到该批处理所在目录）；用 `--repo-root` 启动时以参数为准。启动后自动回填，无需手工填写。
- 列出入库工具解释器（含 Python 版本）、入库脚本、入库日志目录、处理工具解释器、QGIS（`qgis_process`）及其**存在/缺失**状态。
- 点 **「检测环境」** 按钮做一次完整检测（含解释器能否导入依赖）：结果用**浮层提示**（「环境正常」/「检测到缺失/异常：…」），并在下方逐项列出明细。

后续「更新到库」会读取这里的数据库连接与共享目录；数据处理会读取 QGIS 安装目录。

- **数据处理**：把已下载的 SHP 做切分 → 校验 → 清洗 → 3857 重投影。
- **库表更新**：登记哪些区域已更新进数据库。
- **日志**：集中浏览与查看各类日志（见第 9 节）。
- **CSV清单管理**：检查 / 追加任务清单（追加后自动同步到下载状态库，新任务加入下载队首）。
- **配置**：配置数据库连接、共享目录、QGIS，并可检测环境。

> 若启动看板时设置了 `--action-token`，控制类/删除类操作会先弹出令牌输入框（令牌保存在浏览器本地）。

> 打开看板时会**自动检查配置**：`data/config.json` 随仓库自带（通常已配置）；若文件缺失或环境项缺失，页面**顶部会出现红色提示条**。点「去配置」按第 3 节填写并点「检测环境」；点「关闭」后**本会话不再提示**。

## 5. `world_building_download_tasks.csv` 的来源

这份清单是下载与处理任务的**事实来源**，由脚本从 PostgreSQL 数据库导出生成：

- 来源：PostgreSQL 表 `world_building`（按 `continent / country / city` 分组去重）。
- 生成脚本：`scripts/export_world_building_tasks.py`，默认输出 `data/world_building_download_tasks.csv`。
- 五列含义：

  | 列 | 含义 |
  | --- | --- |
  | `continent` | 洲 |
  | `country` | 国家 |
  | `city` | 城市/区域（第三级目录名） |
  | `download_dir` | 下载目录，规则为 `data\洲\国家\城市` |
  | `process_name_prefix` | 命名前缀，取 `shp_name` 第一个下划线前的部分 |

本质上，**这份清单反映“数据库里已登记的区域”**，因此下载与处理都围绕它展开。

### 在「CSV清单管理」页检查与追加任务（推荐）

不用手工编辑 CSV，「CSV清单管理」页即可完成：

1. **检查**：输入城市 / 国家 / 洲关键词点「查询」，分别显示该任务在**任务清单**与**下载状态库**中的存在情况（含行号与状态）。
2. **追加**：填写 洲 / 国家 / 城市 / 命名前缀（**中英文均可、需全局唯一**，如 `Riyadh` / `利雅得`），下载目录按 `data\洲\国家\城市` 自动生成；点「**追加并同步**」→ 先向 CSV **末尾**追加一行，再同步到状态库；**新任务按 CSV 顺序插入队列队首，已有任务相对顺序不变**。**同步后该任务才会出现在「建筑数据下载」队列中**。
3. **后续**：新任务默认已在队首；下载运行中无需重启，当前任务完成后优先执行；下载未运行时点「开始下载」即可。
4. **运行中新增与全量同步的区别**：下载运行中可通过「追加并同步」**只新增任务**，不会修改已有任务；如果要修改已有任务、执行全量对账或 `--sync-only`，需**先停止「建筑数据下载」任务**。若同步被拒（例如全量同步），停止下载后再点一次即可（任务已存在时会自动跳过追加）。清单与状态库存在差异时，②区会显示文字提示。

> 校验规则：四个字段必填、各 ≤100 字符、不允许 `, " < > : * ? | / \` 等字符；任务（洲|国家|城市）与命名前缀不得与**清单 / 下载状态库 / 处理状态库**中已有记录重复；追加会保持清单原编码（UTF-8 / GBK）与换行风格，并原子写入。

### 手动新增任务并同步到状态库

看板下载队列读取的是**状态库**（`data/world_building_download_tasks_state.db`），**不直接读 CSV**；因此手动改 CSV 后必须**同步**一次。

1. 在 `data/world_building_download_tasks.csv` **追加一行**（5 列，逗号分隔，目录用反斜杠）：
   ```
   <洲>,<国家>,<城市>,data\<洲>\<国家>\<城市>,<命名前缀>
   ```
   例：`亚洲,沙特,利雅得,data\亚洲\沙特\利雅得,Riyadh`
   - `continent/country/city`：与既有行风格一致（英文段用英文、中国段用中文）。
   - `download_dir`：固定规则 `data\<洲>\<国家>\<城市>`。
   - `process_name_prefix`：处理命名前缀，需**唯一**，建议用城市拼音/英文 slug。
   - 编码：程序自动识别 `UTF-8/GBK`，用可**选择编码**的编辑器保存为 UTF-8 或 GBK 均可（勿出现乱码）。
2. 同步：由维护人员运行命令行 `python scripts\run_world_building_tasks.py --sync-only`；或在看板「CSV清单管理」页对任一目标任务点一次「追加并同步」。看板运行中新增任务会自动加入队首；命令行/全量同步仍建议先停止下载，避免修改已有任务。
3. 校验：看板「队列（全部待执行任务）」搜索该任务（**按城市名搜索**，中文任务用中文名）；或 `python scripts\run_world_building_tasks.py --summary`。
4. 边界文件 `data\<洲>\<国家>\<城市>\place_boundary.gpkg` 缺失时，系统会先尝试自动解析（覆盖表 → 本地边界 → 在线地名解析），**全部失败**该任务才会失败。

> **差异提醒**：若清单 CSV 与状态库**不一致**（同步会产生新增/更新/重置），看板「**CSV清单管理**」页的 ② 区会显示文字提示（随 15 秒刷新轮询检测）。差异仅为新增任务时，运行中「追加并同步」即可；差异涉及已有任务修改时，需先停止下载再做全量同步。

### 术语速查

| 术语 | 含义 |
| --- | --- |
| 洲 / 国家 / 区域 | 任务的三级划分，对应 `download_dir` 的三级目录 |
| 命名前缀 `process_name_prefix` | 处理阶段文件名的开头，取自清单第 5 列 |
| 交付 SHP | 可直接使用的成果 `<前缀>_buildings_height_gba.shp` |
| 分卷 | 数据量超过阈值时拆分出的 `..._part1.shp`、`..._part2.shp`… |
| 等待重新下载 | 某区域的原始数据被删除、待重新下载时处理任务的中间状态 |
| 库表更新 | 登记各区域是否已入库的看板页签（数据存 `data/db_update_status.json`） |

## 6. 建筑数据下载

### 如何下载

> **按钮状态说明**：下载未运行时，主按钮显示「开始下载」；下载运行中，主按钮显示「重启下载」。点击「重启下载」会先停止当前下载并重新排队，已完成分块会复用。

下载任务来自**任务清单** `data/world_building_download_tasks.csv`（其来源见第 5 节）。点击「开始下载」后，看板会按**状态库中的队列顺序**从头开始逐条下载待执行任务（支持断点续跑）：

1. 打开看板「建筑数据下载」页签，在「队列（全部待执行任务）」确认目标区域在队列中（可按城市搜索；若不在，到「CSV清单管理」页检查 / 追加，见第 5 节）。
2. （可选）调整执行顺序：搜索目标区域并点「⤒ 置顶」，详见下「如何修改优先级」。
3. 未运行时在「批处理控制」点「**开始下载**」；已运行则无需操作，当前任务完成后按队列继续。顶部显示“批处理：运行中”。
4. 观察进度：「当前任务」区显示正在下载的任务；完成的区域进入「最近完成」列表。
5. 下载成功的任务**自动登记到「数据处理」队列**，之后到「数据处理」页签直接处理即可；失败任务进入「失败任务」列表（可「重新入队」，见下）。

随时点「停止下载任务」可停止；再次点「开始下载」继续（已完成分块复用，断点续跑）。

本页按钮说明：

- **开始下载 / 重启下载（同一按钮，按运行状态切换）**：未运行时显示「开始下载」，按**最新队列顺序**启动下载；运行中显示「重启下载」，会先停止当前批处理并重新启动，按**最新队列顺序**重新选取任务。两种情况均复用已完成分块，任务断点续跑（重启约有数秒中断，已下载数据不受影响）；被中断的任务会从 `RUNNING` **重置回待执行队列**（保留原队列位置），不会留下没有 worker 的“运行中”记录。
- **停止下载任务**：停止当前下载批处理（不重启）；被中断的任务同样回到待执行队列，之后可再点「开始下载」继续。
- **队列排序无需点「重启下载」**：排序写入后，当前任务完成时自动按新顺序选择下一个任务。
- 清单检查 / 追加（追加后自动同步到状态库）已移至「**CSV清单管理**」页签（见第 5 节）。

### 如何修改优先级

下载队列按「队列（全部待执行任务）」表格中「#」列的顺序执行（点「开始下载」时从第 1 位开始依次下载）。**CSV 新增任务同步后默认插入队首，已有任务相对顺序不变**。修改方法：

1. 找到目标任务：用「搜索城市」按中英文模糊搜索（如 `安哥拉` / `Angola`），或翻页定位。
2. 在目标行「排序」列操作：
   - `↑` **上移一位**、`↓` **下移一位**（按全局队列顺序移动，跨页也有效）；
   - `⤒` **置顶**：直接排到全局队首；**搜索命中的行同样可用**（不限于当前页第一条）。
3. 改动会**立即写入状态库**（表格顺序当即刷新）。runner 每完成一个任务都会重新读取最新队列，因此**正在下载的任务不会中断**，当前任务完成后自动按新顺序选择下一个任务。
4. 生效时机：
   - 批处理**未运行**：下次点「开始下载」即按新顺序执行；
   - 批处理**运行中**：**无需重启**，当前任务完成后按新顺序执行；
   - 若必须立即切换当前正在下载的任务，需先「停止下载任务」（当前任务会回到待执行队列，已完成分块复用），再重新开始。

> 示例——想让“沙特 / 利雅得”最优先下载：在「搜索城市」输入 `利雅得` 点「搜索」→ 点该行 `⤒`。若下载正在运行，当前任务完成后利雅得优先执行，不需要重启下载。

其他会改变任务位置的操作：

| 所在区 | 操作 | 效果 |
| --- | --- | --- |
| 失败任务 | 重新入队 | 重置为待执行并**置顶队首**（清空尝试次数与最后错误，不删除已下载数据）；当前任务完成后优先执行 |
| 最近完成 | 重新下载 | 删除该区域下载目录，重置为待执行并**置顶队首**（「重下次数」+1，详见下）；当前任务完成后优先执行 |
| 当前任务 | 停止当前任务并加入队尾 | 停止整个下载批处理，把该任务**排到队尾**；再次点「开始下载」恢复下载 |

队列区其余按钮/控件：

- `搜索城市` + **搜索** / **清除**：按城市中英文模糊搜索、清空搜索。
- `每页`（15/30/50/100/200）+ **首页 / 上一页 / 下一页 / 末页**：分页浏览。
- 工具栏分左右两组（左：搜索；右：分页）；表格**表头在页面滚动时置顶**。

### 当前任务

下载进行中时，「当前任务」区显示正在下载的任务。

- **停止当前任务并加入队尾**：停止整个下载批处理，并把该任务排到待执行队尾；再次点「开始下载」后，runner 会按最新队列顺序执行（已完成分块复用）。

### 最近完成（重新下载）

最近完成列表每页 10 条，显示总条数和当前页，支持「首页 / 上一页 / 下一页 / 末页」翻页。

在「最近完成」列表中，每行有：

- **重新下载**：删除该区域的下载目录，重置为待执行并**置顶到队首**（「重下次数」+1，当前任务完成后优先执行）；对应处理任务转为「等待重新下载」（下载完成后自动恢复为待处理）；同时**删除该区域在「库表更新」页签的记录**（需重新入库登记）。

### 失败任务（重新入队）

下载失败的任务会出现在「失败任务」列表。

- **重新入队**：把该任务重置为待执行并**添加到队首**（清空尝试次数与最后错误，**不删除已下载数据**），当前任务完成后优先执行。

## 7. 数据处理

把下载完成的 SHP 依次做：切分 → QGIS 有效性校验 → 清洗 → EPSG:3857 重投影。

### 如何设置处理数量

1. 打开看板「数据处理」页签。
2. 点「同步队列」，把可处理的数据登记进队列（下载完成的任务会**自动登记**，这里用于补充历史数据或手动合并后的数据）。
3. 处理数量在「配置」页「数据处理 → 处理默认数量」设置（`0`=全部）；点「开始执行」时才读取，**保存配置不会改变正在运行的执行器**，需先「停止处理」再「开始执行」才会按新数量执行。处理运行中，处理控制区会显示「本次数量」。
4. 需要时勾选「资源不足时等待」（内存/磁盘不足时自动等待）。
5. 点「开始执行」；点「停止处理」可停止（停止时会先确认处理进程完全退出，再把进行中的任务重置为待处理，可再次开始续跑）。

处理控制区按钮/控件：

- `本次数量`：处理运行中显示**当前执行器实际使用的数量**（启动时取自「配置」页「处理默认数量」，`0`=全部；未运行时显示"-"）。若「配置」数量是在这批任务启动后才修改的，仍显示启动时的数量（如"全部"），属正常现象——先「停止处理」再「开始执行」即按新数量执行。
- `资源不足时等待`：内存/磁盘不足时自动等待，满足后再继续。
- **开始执行**：在后台启动处理队列（独立进程，重启看板不影响）；SHP≥2 且未合并的任务会被**跳过**（见「多个 SHP 先合并为一个」）。
- **停止处理**：停止处理队列；停止后会检查处理进程是否完全退出，确认干净后才把正在跑的任务重置为待处理（可再次续跑）。若提示「处理进程未完全停止」，任务会保持 RUNNING 状态，请稍后重试「停止处理」，确认页面显示“未运行”后再重新开始（开始执行前也会拦截残留的处理进程）。
- **同步队列**：扫描可处理的数据并登记进处理队列。

### 多个 SHP 先合并为一个

当数据量超过阈值时，交付成果会被拆成多个分卷 `..._part1.shp`、`..._part2.shp`…

**合并的原因：为了同初版数据库中的命名保持一致**（数据库按单个 `shp_name` 命名，分卷会导致命名对不上）。

**未合并不会被处理**：待处理队列中 SHP≥2 的任务，「状态」列显示橙色徽标「**待合并**」（悬浮显示「需先合并（N 个分卷）后方可处理」），点「开始执行」时这些任务会被**跳过**（日志打印 `[SKIP] ... 需先合并`），只有在合并为 1 个 SHP 后才会进入处理；SHP 为 1 个时「自动合并」按钮置灰（无需合并）。合并完成后「状态」列恢复「待处理」、按钮转灰。

有两种合并方式：

**方式一：自动合并（推荐）**

1. 在「待处理队列」表格中，找到该区域这一行（「SHP」列显示多个，「状态」列显示橙色徽标「待合并」）。
2. 点该行末尾的「自动合并」按钮，确认后系统在后台用本机 QGIS/GDAL 自动合并为一个 SHP。
3. 合并进行中：「状态」列显示灰色徽标「**合并中…**」、「自动合并」按钮**保持禁用**；成功后自动**删除原分卷**并**自动同步队列**（该行「SHP」变为 1、「状态」回到「待处理」）；失败则「状态」列显示红色徽标「**合并失败**」。
4. 若失败：「状态」列显示**可点击的红色徽标「合并失败」**——**持久显示**（刷新页面 / 重启看板后仍在），点击跳到「日志」页并展开该任务的 `merge_<前缀>.log`（见第 9 节）；鼠标悬浮可看失败原因。失败与「待合并」提示仅在 `SHP≥2` 时显示；手动合并（=1 个 SHP）+ 点「同步队列」后自动消失。
   - 若因**单文件预计超过 2GB（Shapefile 上限）**失败，「合并失败」徽标的**悬浮提示**会给出建议：**「单文件超 2GB，请手动合并为单个 SHP 后点「同步队列」」**（按「方式二」处理后即消失）。

**方式二：手动合并**

1. 在 **QGIS** 中打开这些分卷 SHP。
2. 使用「矢量 → 数据管理工具 → 合并矢量图层」（Merge Vector Layers）合并为一个图层。
3. 导出为一个 SHP，命名与数据库保持一致（形如 `<前缀>_buildings_height_gba.shp`），放回原区域目录，并删除原分卷。
4. 回到看板「数据处理」页签点「同步队列」。系统会按新的 SHP 文件重新扫描与登记：按**合并后的 SHP 数量**更新任务，源文件变化时会把该区域已完成的任务自动重置为待处理。

确认数量无误后，再按上面的方式「开始执行」（处理数量取「配置」页的「处理默认数量」）。

「待处理队列」其余按钮/控件：

- 「排序」列 **↑ 上移 / ↓ 下移 / ⤒ 置顶**：调整处理顺序（下次执行处理生效）。
- 「状态」列：显示 `待处理 / 待合并 / 合并中… / 合并失败`（徽标；“合并失败”可点击跳「日志」，见第 9 节）。
- 「操作」列 **自动合并**：SHP 多于 1 个时可用；SHP 为 1 个时**置灰**（无需合并）。见上「多个 SHP 先合并为一个」。
- 「操作」列 **打开目录**：**仅自动合并失败时**出现；点击由看板在**本机资源管理器**打开该任务来源目录 `data/<洲>/<国家>/<区域>`（需看板与数据在同一台机器、且以交互会话运行，如 `启动.bat`）。
- 「待处理队列」与「最近完成」表格的**表头在页面滚动时置顶**。

### 重做处理 / 重新下载

在「最近完成」列表中，每行有「操作」列，两个按钮含义不同：

| 按钮 | 作用 | 删除下载数据 | 库表更新记录 |
| --- | --- | --- | --- |
| **重做处理** | 删处理产物与输入副本（**保留下载数据**）→ 重置待处理并置顶 | 否 | **重置为未更新** |
| **重新下载** | 删**下载目录** + 处理产物 → 退回下载队列重下（与下载页的「重新下载」是**同一操作**） | 是 | **删除该记录** |

- 点「重新下载」后，该区域在「数据处理」中会变成 **“等待重新下载”** 状态（左侧计数卡片可见），不会出现在「待处理队列」里，避免误导。
- **自动恢复**：重新下载完成后，系统会自动把它改回「待处理」，无需手动点「同步队列」（前提是未关闭自动登记）。若使用了 `--no-process-sync`，则需手动点「同步队列」。
- 最近完成分页：`每页`（10 条）+ **首页 / 上一页 / 下一页 / 末页**。

> **重做类按钮一句话对照**：**重新下载**＝删下载数据 + 删处理产物 + **删**库表更新记录；**重做处理**＝保留下载数据 + 删处理产物 + 库表更新记录**重置为未更新**；**重新入队**＝只重置入队，**不删任何数据、不改库表更新记录**。

左侧卡片（计数）：

- 处理任务、运行中、待处理、已完成、**等待重新下载**、失败/阻塞。

### 失败 / 阻塞

- **重新入队**：把失败任务重置为待处理并**添加到队首**（清空阶段与错误，尝试次数保留），下次执行处理时生效。
- 「等待重新下载」是另一类状态（见上），不属于「失败 / 阻塞」。

## 8. 如何进行库表更新

处理完成后，把成果交付并写入数据库，再在看板登记。

### 交付并写入数据库

1. 把处理结果交付到共享目录（**两种方式任选**）：
   - **自动拷贝（推荐）**：点该行「操作」列的「**拷贝到共享目录**」——会**先清空**共享目录该区域 `<配置的共享目录>\<洲>\<国家>\<区域>\` 下的**文件**（保留子目录；目录不存在则**逐级自动创建**，如 `\\<服务器>\BuildingData\AutoGenerete\亚洲\沙特\利雅得`），再把处理产物 `out_data/<前缀>_pipeline/final/*_3857.shp`（含 sidecar）逐个拷入（进度「拷贝中 x/y」）；**全部拷贝且校验一致**（每个文件存在且大小一致）后，**删除 `final` 下的内容**；拷贝失败/中断则**不删除 `final`**，可重跑。拷贝过程会追加写入该区域的库表更新日志 `data\logs\update\log_main3_<国家>_<区域>.log`（与入库共用同一份日志），记录**源目录、目标目录、开始/结束时间、文件数、校验结果**；可在「日志 → 库表更新」查看。
   - **手动拷贝**：自行把 `final` 的内容拷到共享目录（保持原文件名）；可选地在完成后清空 `final`。
   「库表更新 → 未更新到库」列表显示 **数据拷贝状态** 列（「更新到库」列表不显示该列）：`未拷贝` / `拷贝中 x/y` / `已拷贝` / `拷贝失败`；状态持久化在 `data\db_copy_status.json`，刷新或重启看板后可恢复。顶部汇总显示「已拷贝 / 拷贝中 / 未拷贝 / 拷贝失败」数量；`已拷贝` 可悬浮查看源目录、目标目录和完成时间；`拷贝失败` 为红色徽标，行内提供「查看日志」链接，点击可跳转查看失败原因。未通过看板拷贝过的旧任务按 `未拷贝` 显示，可直接点「拷贝到共享目录」重新记录状态。
2. 到「**更新到库**」点该行按钮：
   - 前置要求**共享目录内容齐全**：若 `final` 仍在，则共享目录需包含 `final` 的全部文件（名称一致、大小一致，适用于手动拷贝）；若 `final` 已清空（自动拷贝完成）则共享目录非空即可。**拷贝中断（缺文件/大小不一致）会被拦截**，提示先「拷贝到共享目录」。
   - 通过 → 后台**以共享目录内容为准**执行入库（删除该 洲/国家/区域 旧记录，再按目录内每个 `*.shp` 的 3857 包围盒写入 `world_building`），成功后**自动登记为「已更新」**。
   - 结果用**浮层提示**：成功「入库完成，已登记为已更新」、失败「入库失败：<原因>」；入库进行中按钮**保持禁用**。

> 数据库连接与共享目录取自看板「配置」页签。若需手动执行，命令等价于：
> ```powershell
> & "Tools\twopyshp2pgsql\.venv\Scripts\python.exe" "Tools\twopyshp2pgsql\main3_region.py" `
>   --continent "<洲>" --country "<国家>" --region "<区域>" `
>   --root "<共享目录>" --log-dir "data\logs\update"
> ```
> 运行日志保存在 `data\logs\update\` 目录。

### 在看板上登记

- **更新时间**：由入库成功后自动填入，**只读**（仅「更新到库」栏显示）。

本页按钮/控件：

- **按大洲统计**：页面顶部（子选项卡上方）按大洲展示**实际任务总数 / 建筑数据已下载数 / 建筑数据未下载数 / 已更新到库数 / 完成率**，并显示全部数据的汇总；已更新/未更新基于已处理任务，实际任务总数与建筑数据未下载数来自下载任务清单（含未处理任务）；「建筑数据未下载」**只统计待下载（`PENDING`）任务**，下载中、失败、跳过以及已完成处理或已登记更新到库的任务均不计入，统计基于全量数据，**不受搜索和翻页影响**。

## 9. 日志

顶栏「日志」页签集中浏览与查看各阶段日志，分三类（默认折叠）：**建筑数据下载 / 数据处理 / 库表更新**。

- **分类 → 任务 → 文件**：下载按区域（`data/<洲>/<国家>/<区域>/`）、处理按区域（`out_data/<前缀>_pipeline/stdout.log` 与 `merge_<前缀>.log`）、库表更新按单个日志文件；点分类标题展开，再点任务展开其日志文件。左侧列表在每次进入「日志」页签时自动加载，**按日志生成时间倒序排列（最新的在最上面）**，同一任务内的日志文件也按时间倒序。
- **查看区（右侧）**：**选中左侧某个日志文件后才出现**；显示**末尾 200 行**（超出时顶部提示实际总行数）；选中日志即自动加载；打开后可点 **「刷新」** 重新读取最新写入内容，刷新后自动滚动到底部。
- **说明**：**空日志文件不显示**；库表更新项显示名**省略 `log_main3_` 前缀**（磁盘路径不变）；看板**只按任务列出**，不列下载/处理「执行器总日志」（`data/logs/download/run.log`、`data/logs/process/run.log`）。
- **失败排查联动**：处理页「失败」、库表更新页「入库失败 · 查看日志」点击后会跳到本页并展开对应任务（见第 7、8 节）。
- 各类日志文件位置见第 11 节「日志路径」。

## 10. 常见问题

- **`git pull` 连不上 GitHub**：使用代理（见第 3 节「拉取更新」，`-c http.proxy=...`）；无代理时删掉该参数。
- **报 `No Python at '...'`**：说明拷贝了别的机器的 `.venv`（不可移植）；删除后运行对应工具的 `setup.ps1` 重建。
- **数据处理报 QGIS 相关错误**：确认已安装 QGIS，并在「配置」页「QGIS 安装目录」填对路径（等价环境变量 `QGIS_DIR`）；如果 `qgis_process-qgis.bat` 不在 `<QGIS>\bin` 下，直接在「qgis_process 批处理文件」填完整路径（等价 `QGIS_PROCESS_BAT`）。未配置时回退到 `Tools/Oneshp_pipline_qgis/src/shp_pipeline_qgis/paths.py` 的默认值。
- **「更新到库」失败**：确认看板所在机器能访问「配置」页填写的**数据库**与**共享目录**；且共享目录内容需**齐全**（手动拷贝要与 `final` 同名同大小；自动拷贝完成即可），否则会被拦截（见第 8 节）。
- **点「开始执行」没反应**：先确认已「同步队列」（队列非空）；再看 `data/logs/process/run.log`；若提示资源不足，勾选「资源不足时等待」或先释放磁盘/内存。
- **「配置」里改了「处理默认数量」，但「本次数量」还显示"全部"**：属正常现象——「本次数量」显示的是**当前正在运行的执行器**实际使用的数量，配置数量只在**下一次**「开始执行」时生效。需要按新数量执行时：先「停止处理」，再「开始执行」（已完成的处理结果不受影响）。
- **下载不动**：确认批处理已启动、待执行队列非空；源站有限流（约 60 请求/分钟），过密会变慢或等待重试。
- **「当前任务」有中断的信息（任务卡在"运行中"、实际已无进程）**：建议按顺序处理——先在「建筑数据下载」页点「**停止下载任务**」（处理任务同理，点「**停止处理**」）→ **重启看板**（关闭看板窗口后重新双击 `启动.bat`）→ 再点「**开始下载**」**续跑**（已完成分块复用，断点继续）。
  > 说明：直接结束看板进程不一定会同步结束它启动的下载/处理进程；为避免残留进程和状态不一致，先「停止」、再重启看板、最后「开始下载」最稳妥，且不会丢失已完成的分块。
- **为什么「运行中」会出现两个任务？**：正常下载批处理只有一个 worker，**同一时间只应有一个 `RUNNING` 任务**。旧逻辑在「重启下载 / 停止下载任务」时只结束进程、没有把被中断任务从 `RUNNING` 改回待执行；新 runner 又按队列顺序启动了另一个任务，于是看板同时显示“一个真实运行 + 一个无 worker 的疑似中断”。新版已在停止/重启时自动把中断任务放回待执行队列（保留原队列位置）。若仍看到该现象，点一次「停止下载任务」再点「开始下载」即可修复；不要手动再启动第二个 runner。
- **日志位置**：下载 `data/logs/download/run.log`；处理 `data/logs/process/run.log`；入库 `data/logs/update/`；看板自身 `data/logs/server/server.log`。

## 11. 目录与关键路径

| 路径 | 用途 |
| --- | --- |
| `scripts/` | 主脚本（下载、处理、看板、清单导出等） |
| `data/` | 状态库、边界、下载数据；日志在 `data/logs/`（见下） |
| `Tools/Oneshp_pipline_qgis/` | 数据处理工具（QGIS 管线）与产物 `out_data/` |
| `Tools/Twopyshp2pgsql/` | SHP 入库工具（写入 `world_building`） |
| `docs/` | 文档（本手册） |

### 日志路径

| 日志 | 路径 |
| --- | --- |
| 入库工具 | `data/logs/update/log_main3_<国家>_<区域>.log` |
| 看板自身 | `data/logs/server/server.log`（错误流 `server.err.log`） |
| 归档（历史 / 省级） | `data/logs/legacy/`、`data/logs/download/province/` |
| 单个下载任务 | `data/<洲>/<国家>/<区域>/run.log`（错误流 `run.err.log`） |
| 单个处理任务 | `Tools/Oneshp_pipline_qgis/out_data/<前缀>_pipeline/stdout.log` |
| 合并日志（单个任务） | `data/<洲>/<国家>/<区域>/merge_<前缀>.log` |

> 说明：下载/处理**执行器总日志**（`data/logs/download/run.log`、`data/logs/process/run.log`）仍会生成，但**日志看板不列出**（看板只按任务列出）。
